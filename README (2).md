# Ubuntu-Desktop-Lab

An Ubuntu Desktop virtual machine in Oracle VirtualBox. It is part of my home lab, next to the Windows Server 2022 domain controller (`DC01`) and the Windows 11 client (`PC01-W11`) documented in [active-directory-home-lab](https://github.com/minhvo27/active-directory-home-lab).

This page records how the VM is configured so it can be rebuilt, maintained, and troubleshot. Configuration last checked: 2026-11-23.

## Rebuild in the VirtualBox GUI

1. **Machine → New.** Name `Ubuntu-Desktop-Lab`, type *Linux*, version *Ubuntu (64-bit)*, and select the Ubuntu Desktop ISO.
2. **Hardware:** 4096 MB of memory and 4 processors.
3. **Hard disk:** create a new VDI disk of 40.5 GB.
4. **Settings → General → Features:** Shared Clipboard *Bidirectional*, Drag-and-Drop *Disabled*.
5. **Settings → Display:** Graphics Controller *VMSVGA*, Video Memory 16 MB.
6. **Settings → Network → Adapter 1:** attached to *NAT*, adapter type *Intel PRO/1000 MT Desktop (82540EM)*.
7. Start the VM, install Ubuntu, then install the Guest Additions (see below).

## Rebuild with VBoxManage

Run these in PowerShell on the Windows host. They assume the default VirtualBox install path, and the option spellings follow the VirtualBox 7.x manual (6.x used different names for several options).

```powershell
$vm   = "Ubuntu-Desktop-Lab"
$vbox = "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe"
$dir  = "$env:USERPROFILE\VirtualBox VMs\$vm"
$iso  = "C:\path\to\ubuntu-desktop.iso"

# 1. Create and register the VM
& $vbox createvm --name $vm --ostype Ubuntu_64 --register

# 2. CPU, memory, display, audio, network, USB, clipboard
#    USB 2.0 (EHCI) normally needs the Extension Pack; drop --usb-ehci if the VM will not start.
& $vbox modifyvm $vm `
  --memory 4096 --cpus 4 `
  --nested-paging on --paravirt-provider kvm `
  --boot1 floppy --boot2 dvd --boot3 disk --boot4 none `
  --graphicscontroller vmsvga --vram 16 `
  --audio-enabled on --audio-driver default --audio-controller ac97 `
  --nic1 nat --nic-type1 82540EM --cable-connected1 on `
  --usb-ohci on --usb-ehci on `
  --clipboard-mode bidirectional --drag-and-drop disabled

# 3. Storage: SATA (AHCI) system disk and an IDE optical drive
& $vbox storagectl $vm --name "SATA" --add sata --controller IntelAhci --portcount 1 --hostiocache off
& $vbox storagectl $vm --name "IDE"  --add ide
& $vbox createmedium disk --filename "$dir\$vm.vdi" --size 41472 --format VDI   # 40.5 GB
& $vbox storageattach $vm --storagectl "SATA" --port 0 --device 0 --type hdd --medium "$dir\$vm.vdi"
& $vbox storageattach $vm --storagectl "IDE"  --port 0 --device 0 --type dvddrive --medium $iso

# 4. Start the VM and install Ubuntu
& $vbox startvm $vm
```

After the install, attach the Guest Additions image to the optical drive. This is the state shown in the Storage section above:

```powershell
& $vbox storageattach $vm --storagectl "IDE" --port 0 --device 0 --type dvddrive --medium additions
```

## Guest Additions

The Guest Additions provide the shared clipboard and automatic display resizing. Inside Ubuntu:

```bash
sudo apt update
sudo apt install -y build-essential dkms linux-headers-$(uname -r)
cd /media/$USER/VBox_GAs_*/        # appears after Devices → Insert Guest Additions CD image…
sudo sh ./VBoxLinuxAdditions.run
sudo reboot
```

After the reboot, confirm they are running:

```bash
lsmod | grep vboxguest
VBoxControl --version
```

## Networking

Adapter 1 is the only adapter enabled, and it is attached to NAT. The guest can reach the internet, but the host and the other lab VMs cannot reach the guest unless a port-forwarding rule exists. VirtualBox's default NAT addressing gives the guest `10.0.2.15`, with gateway `10.0.2.2` and DNS `10.0.2.3`.

**Optional: SSH from the host.** Install `openssh-server` in the guest, then add a forwarding rule with the VM powered off:

```powershell
& $vbox modifyvm $vm --nat-pf1 "ssh,tcp,127.0.0.1,2222,,22"
ssh -p 2222 <ubuntu-user>@127.0.0.1
```

**Optional: join the lab network.** `DC01` is on the internal network `LabNet`. To let this VM talk to `DC01` and `PC01-W11`, add a second adapter on that network and keep Adapter 1 on NAT for internet access:

```powershell
& $vbox modifyvm $vm --nic2 intnet --intnet2 "LabNet" --nic-type2 82540EM
```

Then give the new interface a static address in the lab's `192.168.50.x` range (Settings → Network in Ubuntu, or netplan). For domain-join tests, point DNS at `DC01`.

## Snapshots and backup

Snapshots are stored in `C:\Users\<username>\VirtualBox VMs\Ubuntu-Desktop-Lab\Snapshots`.

```powershell
& $vbox snapshot $vm take "clean-install" --description "Fresh Ubuntu install with Guest Additions"
& $vbox snapshot $vm list
& $vbox snapshot $vm restore "clean-install"      # VM must be powered off
& $vbox export $vm --output "$vm.ova"             # portable backup; do not commit it
```

## Day-to-day

```powershell
& $vbox startvm $vm                        # add --type headless to start without a window
& $vbox controlvm $vm acpipowerbutton      # clean shutdown
& $vbox showvminfo $vm --machinereadable   # print the current configuration
```

Keep Ubuntu itself up to date from inside the guest:

```bash
sudo apt update && sudo apt full-upgrade -y
```

## Verify a rebuild

- `ip a` in Ubuntu shows an address on the NAT adapter (usually `10.0.2.15`).
- `ping -c 3 ubuntu.com` succeeds.
- Text copied on the host pastes into the guest, and the other way around.
- The guest display resizes when the VM window is resized.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Clipboard does not work | Guest Additions not installed or not running | Reinstall the Guest Additions, reboot, and confirm Shared Clipboard is *Bidirectional* |
| Display stays small or does not resize | Guest Additions missing, or too little video memory | Install the Guest Additions; raise Video Memory under Settings → Display |
| No internet in the guest | Adapter disabled or cable disconnected | Settings → Network: Adapter 1 enabled, attached to NAT, cable connected |
| VM boots back into the installer | Install ISO still attached and Optical ahead of Hard Disk in the boot order | Eject the ISO, or move Hard Disk to the top of the boot order |
| Guest Additions installer fails to build modules | Missing build tools or kernel headers | Install `build-essential`, `dkms`, and `linux-headers-$(uname -r)`, then rerun the installer |
